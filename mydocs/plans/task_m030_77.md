# Task #77 수행계획서 - v0.1.1 Web Store 게시 후 릴리스 노트와 배포 문서 보정

GitHub Issue: [#77](https://github.com/postmelee/crop/issues/77)
마일스톤: M030

## 목적

Chrome Web Store에 `crop` v0.1.1이 게시된 이후 사용자에게 보이는 GitHub Release note와 반복 release 운영 문서를 실제 배포 상태와 맞춘다.

이번 task는 이미 게시된 Web Store listing, GitHub Release asset, package checksum, README/PRIVACY 상태를 다시 확인한 뒤, `v0.1.1` Release body의 `not submitted` 문구를 published 상태로 보정하고 다음 release에서 버전 하드코딩이 재발하지 않도록 release pipeline guide를 정리한다.

## 배경

사전 조사에서 Chrome Web Store listing URL은 HTTP 200으로 접근 가능했고, listing HTML에서 `crop`, version `0.1.1`, size `121KiB`, privacy URL `https://github.com/postmelee/crop/blob/main/PRIVACY.md`, locale `en`, `ja`, `ko`, `zh-CN` 단서가 확인됐다. GitHub Release 목록에서도 `v0.1.1`이 Latest release로 확인됐고, asset `crop-0.1.1-cws.zip`의 SHA-256 값은 기존 #72 기록과 일치했다.

반면 GitHub Release `v0.1.1` body에는 아직 `Chrome Web Store: not submitted for v0.1.1`, `Store 상태: not submitted`, `Chrome Web Store 제출과 review 완료 후 자동 업데이트 후보`가 남아 있어 사용자-facing release note가 실제 게시 상태와 충돌한다. 또한 `mydocs/manual/release_pipeline_guide.md`에는 반복 절차에 `/tmp/crop-0.1.0-cws.zip`가 하드코딩되어 다음 release에서 오작업을 유발할 수 있다.

README 4개 언어 파일은 이미 Chrome Web Store 설치 안내와 게시 상태를 반영하고, `PRIVACY.md`는 `v0.1.1 and later`와 2026-06-14 업데이트일을 포함하므로 기본 범위에서는 수정하지 않는다.

## 범위

### 포함

- GitHub Release `v0.1.1` body의 Chrome Web Store 상태와 설치/업데이트 문구 보정
- `mydocs/manual/release_pipeline_guide.md`의 package path 예시를 version 일반화 기준으로 보정
- 필요 시 `mydocs/tech/task_m030_37_chrome_web_store_dashboard.md`에 `v0.1.0` 제출 스냅샷 성격을 밝히는 짧은 주석 추가
- 필요 시 `mydocs/tech/task_m030_72_release_candidate.md`에 `v0.1.1` 게시 후 확인 결과를 하단 섹션으로 추가
- 단계 보고서와 최종 보고서 작성

### 제외

- extension source/runtime 변경
- `manifest.json`, `package.json` version 변경
- `v0.1.1` tag 이동, GitHub Release asset 교체, package 재생성
- Chrome Web Store Dashboard 값 변경, upload, `Submit for review`
- README/PRIVACY 수정. 단, 새 불일치가 발견되면 별도 승인 후 최소 보정한다.

## 설계 방향

- GitHub Release body는 기존 구조를 유지하고, Chrome Web Store 상태와 업데이트 문구만 실제 published 상태로 바꾼다.
- Release body의 developer 검증 기록, release commit, asset URL, asset size, SHA-256 checksum은 현재 원격 값과 일치하면 변경하지 않는다.
- `release_pipeline_guide.md`는 특정 release 번호가 아니라 `v{version}` 또는 `/tmp/crop-{version}-cws.zip` 기준을 사용하도록 정리한다.
- #37 Dashboard 기술 노트와 #72 release candidate 문서는 당시 작업 기록이므로 과거 문장을 덮어쓰지 않는다. 필요한 경우 최신 상태를 별도 보정 섹션으로 추가해 이력성과 현재 상태를 분리한다.
- README/PRIVACY는 수정 대상이 아니라 검증 대상으로 둔다.

## 검증 계획

### 단계별 검증

- Stage 1
  - `gh release view v0.1.1 --repo postmelee/crop --json tagName,name,url,isDraft,isPrerelease,publishedAt,targetCommitish,assets,body`
  - `curl -L -I https://chromewebstore.google.com/detail/crop/pdmniipgbjdcpnhbkkppodechbehagki`
  - `rg -n "Release status|Chrome Web Store에서 설치|Chrome Web Store からインストール|从 Chrome Web Store 安装|v0.1.1|2026년 6월 14일|2026年6月14日" README*.md PRIVACY.md`
- Stage 2
  - `gh release view v0.1.1 --repo postmelee/crop --json body,assets,isDraft,isPrerelease`
  - `rg -n "not submitted|published|crop-0.1.0-cws.zip|crop-\\{version\\}-cws.zip|/tmp/crop-\\{version\\}-cws.zip" mydocs/manual/release_pipeline_guide.md mydocs/tech/task_m030_37_chrome_web_store_dashboard.md mydocs/tech/task_m030_72_release_candidate.md`

  - `gh release list --repo postmelee/crop --limit 5`

  - `git diff --check`

### 통합 검증

- GitHub Release `v0.1.1` body가 Web Store published 상태와 설치 URL을 설명한다.
- GitHub Release `v0.1.1`의 tag, title, draft/prerelease 상태, asset 이름, asset size, SHA-256 checksum은 변경되지 않는다.
- `release_pipeline_guide.md`의 반복 release 절차가 현재 버전에 묶인 `/tmp/crop-0.1.0-cws.zip` 경로를 새 기준으로 사용하지 않는다.
- README/PRIVACY를 수정하지 않았거나, 수정했다면 별도 승인 근거가 최종 보고서에 남아 있다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **원격 Release body와 저장소 커밋의 불일치**: GitHub Release body는 저장소 파일이 아니므로 최종 보고서와 단계 보고서에 수정 전후 확인 결과를 남긴다.
- **과거 산출물 훼손**: #37/#72 문서는 당시 판단 기록이다. 기존 문장을 최신 상태처럼 덮어쓰지 않고 별도 보정 섹션을 사용한다.
- **게시 상태 재확인 한계**: Chrome Web Store는 동적 페이지다. HTTP 200과 listing HTML의 version/URL 단서를 기록하되, Dashboard 내부 상태는 작업지시자가 직접 확인한 게시 완료 사실을 기준으로 삼는다.
- **Release asset 변경 오해**: 이번 task는 body와 문서만 보정한다. tag, asset, package, manifest version은 변경하지 않는다는 검증을 반복한다.

## 승인 요청 사항

- GitHub Release `v0.1.1` body의 Chrome Web Store 상태를 `published` 기준으로 보정하는 범위를 승인한다.
- `mydocs/manual/release_pipeline_guide.md`에서 package path 예시를 version 일반화하는 범위를 승인한다.
- #37/#72 기술 노트는 과거 기록을 유지하고 필요한 경우 최신 상태 보정 섹션만 추가하는 방향을 승인한다.
- README/PRIVACY는 이번 task의 수정 대상에서 제외하고 검증 대상으로만 두는 방향을 승인한다.

승인되면 `task_m030_77_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
